# Skills audit, 2026-08-18 (todo 58)

Follow-up to the 2026-08-01 audit (12 deletions, 3 merges). This pass covered **83 skill
directories** and produced a keep / update / remove verdict for every one.

## Headline

**Nothing was removed, and that is the finding.** The 2026-08-01 pass did the pruning; a month
later two independent reviewers checking 16 dormant skills against the live filesystem found zero
dead ones. The real problem was not dead skills, it was **always-on context cost**.

| metric | before | after |
|---|---|---|
| model-invocable skills | 45 | **32** |
| always-on description chars, every session | 10,445 | **5,892** |

**43.6% of the always-on budget reclaimed, zero capability lost.** Every flagged skill still works
when typed as `/name`.

## Method

Evidence came from a 31-day transcript corpus: `C:\Users\tecno\.claude\projects`, 2621 sessions,
2026-07-18 to 2026-08-18. Four measurements, all re-runnable:

1. Invocation counts per skill (slash-command expansions plus Skill-tool calls).
2. Always-on description cost per skill, flagged skills counting zero.
3. Dangling-reference scan across every hand-authored skill file. **Result: zero broken paths and
   zero broken cross-skill references.**
4. Untracked runtime spill inside `skills/`.

Contested clusters then went to **two independent reviewers each**, briefed separately, with the
orchestrator resolving disagreements by reading the files itself.

### Corpus caveat that shaped several verdicts

**31 days is not "ever".** A skill that fires once per new project reads 0 if no new project
started. This nearly caused a wrong bulk-flagging of the web-scaffolding chain. Two further
counting errors were caught by reviewers:

- `rojo` shows 3 shell invocations, which reads as "Roblox is dead". It is not: **4 live Roblox
  projects** carry `test.project.json` and `tests/jest.config.luau`, and tests run through each
  project's `scripts/check.sh`, so counting the bare binary undercounts.
- `character-creator` was clustered as Roblox tooling by the orchestrator. It is not; it builds
  character bundles for `claude_usage_in_taskbar`, and its output directory is populated.

## The mechanism this audit turns on

A skill's frontmatter `description:` loads into **every** session. That is the only always-on cost.
`disable-model-invocation: true` drops it to zero while `/name` keeps working.

**It is not free.** A flagged skill leaves the Skill-tool listing, so anything invoking it *through
that tool* breaks. `close/SKILL.md:189` is explicit: *"Invoke each via the `Skill` tool with its
args."* Other callers reference a file path instead (`test-flow` reads
`skills/flutter-e2e/SKILL.md`), and those are unaffected. **Check which kind a caller is before
flagging anything.**
